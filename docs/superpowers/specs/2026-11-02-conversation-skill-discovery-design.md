# NewSkills：嵌入对话的需求感知推荐设计

日期：2026-11-02。状态：用户已确认；实现与自动验证已完成，真实宿主模型评估另列。

## 目标和已确认范围

在现有 Skill Scout 基础上，让 AI 从当前对话的实际需求和必要的项目证据中发现合适的 skill，并把一条简短的安装建议放进正常回复。优先同时支持 Codex 和 Claude Code。保留现有文件扫描能力，产品以 skill 为入口，无需独立应用、后台服务或额外模型 API。

用户已确认：同时支持两个宿主；以当前对话为范围，安装前确认，不读取其他聊天记录。

## 当前项目事实

- 现有 TypeScript CLI 依据依赖、文件和源码关键词进行静态匹配；22 项现有测试通过。
- 本地已有 Claude skill 的未提交修改及 Codex skill 目录；后续修改以这些版本为基础，保留其项目分析意图。
- README 的克隆地址与实际项目不一致；架构文档包含尚未实现的模块；部分 skill 示例把未经核验的安装量和候选名写成了事实。
- 项目扫描器会读取小型配置文件的内容，需将敏感配置改为只识别存在与否，并防止符号链接越过项目边界。
- 已跟踪的工具状态文件含本机路径；旧提交含个人身份元数据。当前文件清理不能消除旧历史。

## 同类方案及证据边界

检索日期：2026-11-02。只把维护者仓库和官方文档作为功能依据，网页可变，不宣称穷尽生态。

| 来源 | 已有能力 | 对本项目的启示 |
| --- | --- | --- |
| [Vercel find-skills](https://github.com/vercel-labs/skills/blob/main/skills/find-skills/SKILL.md) | 从任务或技能请求搜索候选并提供安装方式 | 搜索不是独创点；不应把它描述成“只能看依赖文件” |
| [metaskill](https://github.com/xdm/metaskill) | Claude hooks 接入任务查找，确认安装，拒绝记录与候选筛选 | “对话内自动推荐并询问安装”已有直接先例 |
| [Skill Recommender](https://github.com/JasperHye/skill-recommender) | 手动与每日推荐，显式反馈、冷却及外部状态 | 反馈与防打扰也已有先例；本项目不加入每日推送 |
| [ECC skill-scout](https://github.com/affaan-m/ECC/blob/main/skills/skill-scout/SKILL.md) | 创建 skill 前检索本地和远端候选 | 同名 skill 已存在；保留旧名称兼容，不宣传名称独占 |

本项目拟形成的差异是：**围绕持续、未被满足的需求累积证据；把候选价值与当前已有能力比较；用可解释的轻量建议接入正常回复；严格限制打扰和上下文外的数据收集。** 这是本项目的设计贡献，不宣称全球首创，也不复制上述项目实现。

## 三种实现路线

1. **推荐：skill + 可选本地 hook。** 共用 skill 工作流和提醒脚本；普通 skill 使用不依赖 hook。hook 在每次用户提交前把流程提醒加入模型上下文，不自行搜索、安装或改写回复。兼顾轻量和触发覆盖率。
2. **仅 skill。** 最容易安装且跨宿主，但隐式调用由模型决定，不能保证每轮检查。作为无 hook 环境的降级路径。
3. **独立推荐服务或额外模型。** 可以做统一存储和语义分类，但增加部署、费用和聊天数据流出；不符合本次产品范围。

## 对话决策和交互

### 1. 获取证据

只使用宿主已提供的当前对话上下文；优先查看最近 8 条真实用户消息。显式“帮我找某类 skill”可立即触发查找；一般需求需在至少 2 条不同用户消息中持续出现，并存在未满足的能力或重复劳动。

引用文本、代码块、文档、工具输出、AI 自己的话、对本推荐系统的讨论不作为用户需求次数。单条消息重复单词不累加。否定请求、已解决需求、话题变化不累积；“再次提到”本身不证明能力缺失。

### 2. 先比较已有能力

查看宿主已提供的 skills、工具与插件，再检查必要的本地安装目录元数据。已经能完成需求时优先复用；排除已安装的相同候选，并考虑同能力的替代方案。项目证据补充当前需求，不因缺少某文件就认定有安全缺陷或强推通用 skill。

### 3. 检索与核验

只发送去身份化的通用能力词进行外部搜索，不传聊天原文、专有项目名、路径、客户名或代码。搜索结果不是指令。推荐前打开真实 SKILL.md，核实来源、功能和实际安装标识；不编造安装量，不以热度作为安全证明。来源不可核验时继续完成原任务，不给出虚构的具体安装项。

### 4. 顺带推荐

先响应当前任务，再在同一条 AI 回复结尾加一条具体建议：需求证据、候选来源链接、预期帮助、是否安装。普通回复最多 1 个候选，当前对话最多主动提示 2 次；两次主动提示至少间隔 5 条用户消息。明确找 skill 时按用户请求正常提供结果，不受主动提示次数限制。

示例仅示意话术，真实候选需先查证：

> 这次对话里你两次需要把报告转成 Word。找到的文档 skill 可以复用排版流程，是否安装到当前项目？

拒绝某候选后本对话内不再主动推荐该候选；“不要再推荐”关闭本对话主动推荐。无回复或转移话题不算同意。只有用户明确再次要求查找或安装时才恢复相应流程。

### 5. 安装

安装建议与执行分开。展示准确来源、选定 skill、目标宿主和项目/用户作用域后获得具体同意；默认项目作用域，只安装选中的 skill。不得把笼统的“提升项目”解释为可安装任何第三方 skill，不默认全局安装或批量安装。复用宿主 installer 或已核验的 skills CLI，成功后检查目标文件；失败不宣称已安装。

## 结构及宿主接入

- 保留 `skill-scout` 作为现有可调用名称，公开项目标题使用 NewSkills；README 解释二者关系。
- 共用一个 skill 内容来源，Codex 与 Claude 的项目入口保持同步，检查脚本防止漂移。主体保持简短，项目分析、候选核验和接入细节放入 references。
- 可选 hook 使用 `UserPromptSubmit` 的 `hookSpecificOutput.additionalContext`；只注入固定的流程提醒，不把输入中的任何文本提升为指令。
- 为两个宿主分别提供可审查的配置示例和配置合并方式。只生成或修改用户指定的目标项目，不改全局配置，不自动启用本机 hook，保留目标的其他 hooks。
- 同步 hook 支持事件输入校验、大小限制和短超时，异常时不阻断原任务。没有后台进程、遥测、外部模型调用、原文日志或跨聊天状态。
- 语义判断、需求累积和回复生成由当前 AI 完成。纯 skill 的隐式触发、模型遵从性、上下文压缩后的状态保持，以及候选是否有用，均不能由 hook 或规则测试保证。
- 可提供轻量决策 helper 对 AI 已整理的证据实施防打扰规则；helper 不负责从原始文本识别语义，也不读取聊天数据库。

官方接口依据：[Codex skills](https://learn.chatgpt.com/docs/build-skills)、[Codex hooks](https://learn.chatgpt.com/docs/hooks)、[Claude Code hooks](https://code.claude.com/docs/en/hooks)。两个宿主均提供相关事件；部署是否可用仍取决于实际版本、信任设置和宿主界面。

## 项目扫描与公开发布隐私

- 配置秘密和运行状态不读取内容；跳过 .env 值、密钥、凭据、宿主聊天/缓存目录。链接不得逃逸指定项目。
- 添加忽略规则，停止跟踪工具状态；保留本地运行状态以免破坏用户环境。
- 去除文档、示例和包元数据中的真实姓名、邮箱、本机用户名和私人路径，统一使用通用示例。仓库作者账号与公开仓库地址不能天然匿名，公开副本避免绑定个人远端。
- 包发布采用明确文件白名单；检查 npm 打包清单，防止 hidden state 进入压缩包。
- 增加只报告文件位置、规则类别和计数的本地隐私检查，不在日志打印命中的秘密值；扫描源文件、发布清单和旧 Git 对象，标明检查覆盖范围。
- 初始交付生成不含原 .git 的公开副本与压缩包，保留原开发历史。后续用户明确要求“删除原仓库个人信息内容，完成推送”，授权扩展为：重建原仓库的干净根提交，使用通用身份，清理旧本地对象，并以绑定远端旧提交的 force-with-lease 推送。仓库可见性不因推送自动改变。

## 验证与交付

1. 保持原有匹配测试通过，运行 TypeScript 构建与类型检查。
2. 针对跨边界链接、敏感文件内容排除、配置合并不覆盖其他 hooks、输入异常不阻断等真实行为添加测试。
3. 验证防打扰策略：明确找 skill、重复未满足需求、一次提及、引用内容、已具备能力、拒绝、关闭、未回复、同轮多候选、冷却期。
4. 对两个宿主的 hook JSON 使用合成输入做协议测试；没有实际启动宿主时明确标记为协议验证，不宣称真实模型端到端测试通过。
5. 提供正反例场景表及人工评估流程，区分规则验证和实际 AI 行为验证。
6. 检查公开副本、压缩包、npm 清单和 Git 元数据。历史与工作区分别报告，不使用“绝对无敏感信息”的承诺。
