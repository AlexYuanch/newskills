# 项目证据

只分析用户指定项目；先看依赖清单和目录，最多再读 5–10 个与当前需求有关的源码。更少证据已足够时提前停止，不全盘扫描。

| 证据 | 能支持的推断 | 不能直接推出 |
| --- | --- | --- |
| 多次手工生成 Word + 项目使用文档库 | 有复用排版流程的机会 | 某个未核验 skill 必然有效 |
| 浏览器自动化代码 + 用户反复修复同一流程 | 可寻找浏览器工作流技能 | 只要有 Playwright 就要再装浏览器工具 |
| 存在认证逻辑 + 用户明确要求审计 | 可检索相关审查流程 | 存在认证逻辑就是有漏洞 |
| 未发现测试或 CI | 询问是否在其他目录或服务 | 项目必须装 testing/CI skill |

不要读取 `.env`、凭据、私钥、聊天记录、缓存、运行状态的内容。配置存在可作为元数据；只读依赖名，不把 scripts 值或源码发往搜索服务。跳过符号链接和生成目录。

可选旧扫描器：在本项目运行 `npm run --silent dev -- /path/to/project --json`。它离线返回静态的检索方向，不能证实 skill 当前存在、已经安装、值得安装或来源安全。绝不直接把其标签转为安装命令。

项目推荐报告可列：现有能力、具体需求证据、待核验搜索方向、经核验候选及限制。不要以“缺文件”强推通用技能。
