# 候选核验与安装边界

推荐前实际打开来源仓库的 SKILL.md。记录真实的 `owner/repo@skill`、链接和检索日期；条件允许时记录审查的 commit。确认技能目录、说明的工作流和当前需求相符，并检查是否已安装或已有等效能力。

检查声明及附带脚本是否涉及意外的凭据读取、网络上传、全局配置、批量安装、后台进程或额外付费依赖。不要为“验证”而运行陌生脚本。静态审查不能证明安全或效果；来源声誉、星标和安装量只提供辅助信息。没有数据就省略数字。

有原生 installer 时优先使用。使用 Vercel Skills CLI 前确认当前版本的 `--help`，把精确来源、skill、`--agent` 和作用域映射清楚。常见形式如下（占位符不得直接执行）：

```text
npx skills add OWNER/REPO --skill SKILL --agent codex
npx skills add OWNER/REPO --skill SKILL --agent claude-code
```

默认当前项目，勿自行添加 `--global`、`--all` 或 `--yes`。确切选项以现场帮助为准；不要执行下载内容来“测试”。用户同意一个候选，不代表同意安装另一个来源或给其他宿主同时安装。

来源打不开：标明不能核验，不给出已核验标签。网络、CLI 或安装失败：继续原任务，保留实际失败状态。安装完应核实对应宿主的 skill 文件和来源，不能只看进程退出码。
